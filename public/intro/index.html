🛠 开发版 · 它是怎么被造出来的

一个零依赖的全栈社区
跑在单文件 Node 上

没有框架、没有构建工具、没有数据库服务。一个 server.js 提供 JSON 接口， 一份 db.json 落盘，前端是一个原生 hash 路由 SPA。下面讲清楚：怎么保障安全、审核怎么流转、 以及每个接口长什么样。

🛡 怎么保障

安全与治理，逐条落地

每一道防线都在后端拦截，不靠前端「藏起来」。

🔑

密码哈希 · scrypt

密码不落明文，scrypt + 随机盐存哈希，校验用 定长比较防时序攻击。登录态走 HttpOnly 之外的 Cookie 令牌 fq_token，boot 时清理本地残留。

🚪

接口按角色分层

每个写接口先查身份：普通用户 / 审核员（`rankOf ≥ 1`）/ 管理员。未登录返 401、越权返 403，一律在写库之前 return。

📝

先审后发

新帖 status='pending'，只有审核通过才进公共列表。转发私信也只放行 approved 或本人作品，堵住「借私信绕过审核」。

🔒

隐私只在后端拦

粉丝 / 关注名单对他人返回 null——只藏前端等于假隐私。举报、封禁、下架都由管理员闭环处理。

🖼

上传双重限制

生成文件名（rid(10)+ext）杜绝路径注入，白名单 png/jpg/gif/webp，单张 5MB；前端先压到长边 1280 再传。

🧱

静态服务防穿越

静态路径 path.normalize 后强制校验必须落在 public/ 内，越界直接 403；目录路径自动补 index.html。

状态机很简单，但每一跳都有权限校验。

🚀 怎么跑起来

三步，零安装

只要一台装了 Node 18+ 的机器。

# ① 直接启动（默认 3000 端口，自动生成 data/db.json） node server.js # ② 想换端口、或指定另一份数据文件（不改动真实数据） PORT=8080 FQ_DB=./data/test-db.json node server.js # ③ 打开浏览器 # http://localhost:3000/ → 社区首页 # http://localhost:3000/intro/ → 本介绍页
📦

依赖：零

package.json 里没有任何 dependencies，用 Node 内置 http / fs / crypto 手写全部逻辑。

💾

存储：一个 JSON 文件

写入走「先写临时文件再 rename」，避免半截数据；每次改动会留 db.backup-*.json 备份。

🎨

前端：单文件 SPA

app.js 一份 hash 路由 + 全量渲染；要局部更新就只改对应容器，保住输入焦点。

🧪

验证：无头浏览器

用本机 Edge + CDP 做端到端冒烟，看截图验布局，不装 Playwright。
